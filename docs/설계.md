# ai-tool-audit 설계

> 개발자 PC의 AI 도구(Claude Code·Codex·Gemini CLI·VS Code·Cursor·MCP 서버) 설정을 읽기 전용으로 점검하고, 근거 사건이 달린 한국어 보고서를 만든다.
> 근거 조사: `docs/research/01~04`. 이 문서의 사실은 그 조사에서 확인한 것만 쓴다.

## 1. 왜 만드는가 — 다른 도구가 비워 둔 자리

조사(`03`)에서 확인한 빈 곳 세 가지가 이 도구의 존재 이유다.

1. **도구를 가로지르는 권한·신뢰 설정 점검.** 기존 도구(Snyk Agent Scan, guardmcp, Nexqor mcp-audit 등)는 MCP 서버 설정·도구 설명 중심이다. Claude Code의 권한 모드·훅, Codex의 `approval_policy`·`sandbox_mode`, Gemini CLI의 `--yolo`·폴더 신뢰, VS Code·Cursor의 작업 공간 신뢰·자동 작업·`chat.tools.autoApprove`를 **홈 폴더의 실제 설정까지** 한 번에 보는 도구는 찾지 못했다.
2. **설치 버전과 공개 보안 권고의 오프라인 대조.** Claude Code 30건, Cursor 33건 등 공식 권고에 고친 버전이 적혀 있다. 권고표를 도구에 넣어 두면 네트워크 없이 "고친 버전보다 낮다"를 판정할 수 있다.
3. **외부 전송 0·다른 프로그램 실행 0, 결과마다 근거 사건이 달린 한국어 보고서.** 가장 큰 도구인 Snyk Agent Scan은 도구 설명·설정을 외부 API로 보낸다. 기업, 특히 금융권은 이것을 받아들이기 어렵다.

## 2. 원칙 (어기면 버그로 본다)

| 원칙 | 구체적으로 |
|---|---|
| 읽기 전용 | 파일을 만들거나 고치거나 지우지 않는다. 예외: 사용자가 지정한 출력 파일과 기준선(baseline) 파일 |
| 외부 전송 없음 | 네트워크 코드를 넣지 않는다. 권고표 갱신은 새 버전 배포로 한다 |
| 다른 프로그램 실행 없음(기본) | `claude --version`도 기본으로는 부르지 않는다. 버전은 설치 폴더·패키지 메타데이터에서 읽는다. MCP 서버를 띄우는 기능은 별도 명령 + 서버마다 동의 |
| 비밀값은 값을 남기지 않음 | 출력에는 규칙·파일·줄 번호·키 이름·앞 4글자만. 메모리 밖으로 값이 나가는 경로를 시험으로 막는다 |
| 읽지 않는 것 | 대화·명령 기록(세션 기록 파일), 셸 히스토리, 프로젝트 소스 내용. 셸 시작 파일(`.zshrc` 등)은 정해진 패턴 일치만 본다 |
| 최소 수집 | 보고서의 사용자 이름은 `~`로, 이메일은 가린다. 합치기용 JSON에는 PC 식별자만 |
| 확인한 것만 단정 | 공식 문서로 확인하지 못한 규칙은 `status: 검토필요`로 두고 "위험"이 아니라 "확인 필요"로 보고한다 |
| 버전을 함께 판정 | 같은 키라도 버전에 따라 효력·기본값이 다르다(예: Claude Code `defaultMode: bypassPermissions`는 일정 버전부터 프로젝트 파일에서 효력 없음). 규칙에 적용 버전 범위를 둔다 |

## 3. 범위

### v0.1 (첫 공개)

- **도구:** Claude Code, Claude Desktop, Codex CLI, Gemini CLI, VS Code(+Copilot 에이전트), Cursor
- **영역:**
  - A. 설치 목록과 버전(설치 폴더·확장 폴더·패키지 메타데이터에서 읽음)
  - B. 권한·자동 승인·샌드박스 설정
  - C. MCP 서버 목록과 정적 점검(버전 미고정 `npx`/`uvx`, 평문 `http://`, 평문 비밀값, 자동 승인)
  - D. 비밀값 위치(AI 도구 설정, MCP `env`·`headers`, 셸 시작 파일의 `export`, 자격 증명 파일 권한)
  - E. 자동 실행(훅, `apiKeyHelper` 류, `.vscode/tasks.json`의 `folderOpen`, 작업 공간 신뢰, `task.allowAutomaticTasks`)
  - F. 셸 시작 파일·별칭의 위험 플래그(`--dangerously-skip-permissions`, `--yolo`, `--trust-all-tools` 등, Nx s1ngularity 근거)
  - G. 버전 ↔ 공개 보안 권고 대조
  - H. 기준선 비교: MCP 서버 **설정** 해시(명령·인자·URL·env 이름)를 저장해 두고 다음 점검 때 새로 생긴·바뀐 서버를 알림(SANDWORM_MODE 근거). 서버를 실행하지 않는다
- **점검 위치:** 홈 폴더의 사용자 설정 + 사용자가 `--repo`로 지정한 저장소 폴더(프로젝트 설정·지시 파일)

## 4. 규칙

### 4.1 이름과 심각도

- 규칙 ID: `도구-분류-번호` (예: `CC-PERM-001`). 도구 약어 CC·CD·CX·GM·VSC·CUR·ALL, 분류 PERM·SBX·MCP·HOOK·SEC·TRUST·TASK·MGMT·INST·VER·BASE
- 심각도: **높음** = 사람 승인 없이 코드가 돌거나 비밀값이 노출됨 / **중간** = 공격 표면을 넓힘 / **낮음** = 권장 미적용 / **정보** = 목록
- 상태: `확정`(공식 문서 확인) / `검토필요`(문서 미확인·엇갈림)
- 기업 PC 전용 규칙(`MGMT`)은 `--enterprise`를 줄 때만 켠다. 개인 PC에서 "관리 정책 없음"을 문제로 보이지 않게 하려는 것이다

### 4.2 규칙 파일 (YAML)

규칙은 코드와 분리해 `rules/*.yaml`에 둔다. 새 AI 도구가 나오면 다른 사람이 규칙만 보태 기여할 수 있게 하려는 것이다.

```yaml
id: CC-PERM-005
tool: claude-code
title: 모든 셸 명령을 묻지 않고 실행하도록 허용
severity: 높음
status: 확정
scope: [user, project, local, managed]     # 어느 설정 층에서 찾는가
detect:
  type: merged_list_contains              # 여러 설정 파일을 합친 목록에서 찾기
  key: permissions.allow
  any_of: ["Bash", "Bash(*)"]
versions: {}                              # 적용 버전 범위(없으면 전 버전)
why: >
  허용 목록에 Bash 전체가 있으면 AI가 만든 셸 명령이 확인 없이 실행된다.
fix: >
  Bash 전체 대신 필요한 명령만 Bash(npm test) 식으로 적는다.
incidents: [nx-s1ngularity-2025]          # data/incidents.yaml의 ID
refs: ["https://code.claude.com/docs/en/permissions"]
```

- `detect.type`은 몇 가지로 고정한다: `json_key_equals`, `json_key_in`, `merged_list_contains`, `toml_key_equals`, `file_exists`, `file_mode_wider_than`, `text_pattern`(셸 시작 파일 등), `mcp_server_check`, `version_below`. 이 틀에 안 맞는 규칙만 파이썬 함수로 쓴다(`checks/` 안, 규칙 ID로 연결)
- 사건은 `data/incidents.yaml`에 한 번만 적고 규칙에서 ID로 참조한다(날짜·원문 URL·한 줄 요약·피해를 키운 조건)
- 권고표는 `data/advisories.yaml`(패키지·권고 ID·영향 범위·고친 버전·URL). 관리자용 갱신 스크립트(`scripts/update_advisories.py`)만 GitHub API를 쓰고, 배포되는 도구는 네트워크를 쓰지 않는다

## 5. 결과물

### 5.1 한국어 보고서 (`report.md`, `report.html`)

1. 한 쪽 요약: 점검 시각, 발견된 AI 도구, 심각도별 건수, 가장 먼저 고칠 3가지
2. 발견 항목: 무엇이 문제인지 → 어느 파일 몇 번째 줄(경로는 `~`로) → 왜 위험한지(근거 사건과 날짜) → 어떻게 고치는지 → 공식 문서 링크
3. `검토필요` 항목은 따로 묶어 "확인이 필요한 설정"으로
4. 끝에 "이 점검이 읽은 파일 / 읽지 않은 파일" 목록(투명성)

### 5.2 JSON (합치기·자동화용)

```json
{
  "schema": "ai-tool-audit/result/v1",
  "tool_version": "0.1.0",
  "scanned_at": "2026-11-24T10:00:00+09:00",
  "host": {"id": "자산번호 또는 해시", "os": "macos", "os_version": "15.x"},
  "inventory": [{"tool": "claude-code", "version": "2.1.x", "source": "~/.local/share/claude/versions"}],
  "findings": [{
    "rule": "CC-MCP-001", "severity": "높음", "status": "확정",
    "file": "~/proj/.claude/settings.json", "line": 12, "pointer": "/enableAllProjectMcpServers",
    "evidence": "enableAllProjectMcpServers = true",
    "fingerprint": "sha256(rule + 파일 + pointer)"
  }],
  "read_files": ["~/.claude/settings.json", "..."]
}
```

- 비밀값 발견의 `evidence`는 `"ANTHROPIC_API_KEY = sk-a…(가림)"` 형태로만
- `fingerprint`는 JSON 포인터 기준이라 파일을 다시 정렬해도 같은 발견으로 본다

### 5.3 SARIF

GitHub code scanning은 저장소 안 파일 위치가 필요하다(`03` 3-1). 그래서 SARIF는 `--repo`로 점검한 **저장소 범위 발견만** 낸다(`.mcp.json`, `.claude/settings.json`, `.vscode/*.json`, `.cursor/mcp.json`). 홈 폴더 발견은 보고서와 JSON으로만 낸다.

## 6. 형태

| 명령 | 하는 일 |
|---|---|
| `ai-tool-audit scan [--repo 경로 …] [--enterprise] [--out 폴더]` | 점검하고 보고서·JSON을 만든다 |
| `ai-tool-audit baseline save` / `baseline diff` | MCP 서버 설정 기준선 저장·비교 |
| `ai-tool-audit rules list` / `rules show <ID>` | 규칙 목록과 설명(근거 사건 포함) |
| `ai-tool-audit files` | 이 PC에서 읽게 될 파일 목록만 미리 보여 줌(아무것도 읽지 않음) |
| `ai-tool-audit mcp-server` | MCP 서버로 실행. 도구: `scan_summary`, `list_findings`, `explain_rule`, `list_mcp_servers`. 모두 읽기 전용이고 다른 MCP 서버를 실행하지 않는다 |

## 7. 기술 선택

- Python 3.11 이상. `tomllib`(3.11 표준)으로 Codex TOML을 읽는다
- 점검기 본체는 **표준 라이브러리만** 쓴다. YAML 규칙은 빌드할 때 JSON으로 바꿔 함께 배포한다(실행할 때 PyYAML을 쓰지 않게)
- MCP 서버 모드만 선택 의존성: `pip install ai-tool-audit[mcp]` → `mcp`(MIT, 2.x의 `MCPServer`)
- 설치: `uv tool install` / `pipx`. 단일 실행 파일(PyInstaller)은 백신 오탐 시험을 거친 뒤 v0.2에서
- 라이선스: Apache-2.0. 비밀값 규칙은 gitleaks(MIT) 규칙 일부를 출처·커밋 해시와 함께 가져오고 `THIRD_PARTY_NOTICES`에 적는다. AGPL(trufflehog·medusa)은 코드·정규식을 가져오지 않는다


## 9. 시험

- **위험 설정 픽스처:** 규칙마다 걸려야 하는 가짜 설정 파일 → 해당 규칙이 잡히는지
- **안전 설정 픽스처:** 기본값·권장 설정 → 아무것도 잡히지 않는지(오탐 시험)
- **비밀값 유출 시험:** 픽스처에 넣은 가짜 키 문자열 전체가 어떤 출력 파일에도 나타나지 않는지
- **읽기 전용 시험:** 점검 전후 픽스처 폴더의 파일 해시·수정 시각이 같은지
- **네트워크 0 시험:** 시험 중 소켓 생성을 막아 두고 점검이 끝까지 도는지
- **실제 PC 시험:** 제 맥에서 실제로 돌린 결과로 확인한다. README 예시는 실제 출력을 가린 것만 쓴다

## 11. 열린 문제 (조사에서 확인하지 못한 것)

- Claude Desktop: MCP 자동 승인 키 존재 여부, 정책 파일 경로(문서끼리 다름)
- Codex: MCP `default_tools_approval_mode` 값의 의미 → 해당 규칙은 `검토필요`
- Gemini CLI: 관리 기능 기본값이 문서끼리 다름
- Cursor: 사용자 `settings.json` 경로, 실행 모드 저장 위치, 작업 공간 신뢰 기본값(보안 업체 보고만 있음)
- VS Code: 신뢰한 폴더 목록 저장 위치, 훅 파일 경로
- 버전마다 바뀌는 키: 실제 설치본(제 맥)으로 확인한 뒤 규칙의 버전 범위를 확정한다
- 도구 정의 해시의 정규화 형식: RFC 8785(JCS)를 따를지 v0.2에서 결정

## 12. LLM 사용 원칙 (사용자 지시 2026-11-24)

- 지금 설계에는 LLM이 없다. 판정은 규칙으로만 한다(외부 전송 없음 원칙과도 맞음).
- 개발 중 LLM이 필요하면(오탐 검토, 규칙 초안 등) `claude -p`로 실행한다.
- 제품에 LLM 기능을 넣게 되면 기본값은 끄고, **어느 회사 어느 모델이든 설정 한 곳만 바꾸면 되게** 만든다. OpenAI 호환 형식(주소·키 환경 변수 이름·모델 이름)을 설정 파일 한 곳에 두고, 코드 안에 회사별 분기를 두지 않는다. 켜면 무엇이 밖으로 나가는지 보고서에 적는다.
