# 회사에 도입할 때 참고할 것

> 아래 내용을 참고해 기업 보안에 유용하게 활용하세요.

## ai-tool-audit가 읽는 것과 읽지 않는 것

| 읽는 것 | 읽지 않는 것 |
|---|---|
| AI 도구의 설정 파일(권한 모드, 허용 목록, MCP 서버 목록, 훅) | 대화 기록·명령 기록(세션 기록 파일) |
| 셸 시작 파일(`.zshrc` 등)에서 정해진 패턴과 맞는 줄 | 셸 히스토리 |
| 설치 폴더 이름·패키지 정보(버전 확인용) | 프로젝트 소스와 문서 |
| 자격 증명 파일의 **권한** | 자격 증명 파일의 **내용** |

비밀값은 값을 출력하지 않고 "어느 파일 몇 번째 줄"만 남깁니다. 실제로 읽는 파일 목록은 `ai-tool-audit files`로 미리 볼 수 있습니다.

이 기본값은 일부러 좁게 잡았습니다. 설정 파일은 "도구가 어떻게 설정됐는가"에 가깝지만, 대화·명령 기록은 직원이 입력한 내용 자체라서 법적으로 더 무겁게 다뤄질 수 있기 때문입니다(아래 3번 참고).

## 도입할 때 챙기면 좋은 것

1. **목적을 한 문장으로 정했는가.** 예: "AI 개발 도구의 위험 설정과 비밀값 노출 위치를 찾아 고친다." 근태·성과 평가·징계 목적이 아니라는 점을 적어 둡니다.
2. **읽는 범위를 목록으로 정해 알렸는가.** 위 표와 `ai-tool-audit files` 결과를 그대로 쓸 수 있습니다.
3. **수집 근거를 정했는가.** 개인정보 보호법 제15조 제1항의 근거(근로계약 이행, 정당한 이익, 동의) 가운데 무엇인지 법무와 정합니다. 개인정보위·고용노동부 가이드는 근거가 분명하지 않으면 미리 알리고 동의를 받되, 최소한만 처리하고 선택권을 보장하라고 합니다.
4. **직원 의견을 들었는가, 노사협의회에서 협의했는가.** 같은 가이드는 근무 공간에 디지털 장치를 도입할 때 미리 의견을 듣고, 노사협의회가 있으면 협의하라고 합니다(근로자참여법 제20조 제1항 제14호). 노사협의회는 상시 근로자 30명 이상 사업장에 둡니다.
5. **개인정보 처리방침에 반영했는가.** 항목·목적·보유 기간을 적고 사내에 공개합니다.
6. **결과를 볼 사람을 최소로 정했는가.** 보안 담당 몇 명으로 한정하고, 인사·현업 관리자는 개인별 결과를 보지 않게 합니다.
7. **보유 기간과 파기 방법을 정했는가.** 조치를 마친 결과는 지웁니다.
8. **결과를 안전하게 보관하는가.** 결과에는 비밀값이 없지만 "어느 PC 어느 파일에 키가 있는가"라는 위치 목록 자체가 공격자에게 지도가 됩니다(NIST SP 800-115 7.4). 암호화해서 보관하고 접근 기록을 남깁니다.
9. **회사 소유 장비로 한정했는가.** 개인 소유 PC(BYOD)를 다룬 공식 근거는 찾지 못했습니다. 회사 장비만 대상으로 하는 것을 기본으로 권합니다.
10. **명령·대화 기록까지 볼 계획이 있는가.** 이 도구는 그 기능이 없습니다. 다른 방법으로 볼 계획이라면 통신비밀보호법 문제까지 별도로 법률 검토를 받으세요.
11. **결과를 징계에 쓸 계획이 있는가.** 가이드는 도입 목적과 다르게 근태 관리·징계에 쓰지 말라고 합니다.

## 금융회사라면

- 전자금융감독규정의 망분리 조항과 금융위원회의 완화 흐름(2024년 8월 「금융분야 망분리 개선 로드맵」 이후)을 함께 확인합니다. 이 도구는 네트워크를 쓰지 않아 내부망 PC에서도 돌릴 수 있습니다.
- 결과 수집은 MDM 보고 칸에는 건수·등급 같은 요약만 두고, 상세 결과는 사내 저장소에 따로 보관하는 방식을 권합니다.

## 배포할 때

- 이 도구는 여러 사용자 설정 파일과 자격 증명 파일 위치를 훑습니다. 정보 탈취형 악성코드와 겉모습이 비슷해 **백신·EDR이 막을 수 있습니다.** 먼저 시범 PC에서 돌려 보고 사내 EDR에 허용 등록하는 절차를 넣으세요.
- Intune·Jamf 같은 MDM으로 배포할 때는 결과 파일 위치와 회수 방법을 정해 둡니다. MDM 보고 칸은 크기 제한이 있고 MDM 관리자 모두가 볼 수 있으므로 요약만 넣습니다.
